# 抽卡卡片独立令牌设计

- 日期：2026-08-19
- 仓库：e:\new-api
- 状态：待用户审阅

## 目标

每张用户抽卡自动获得独立 API 令牌。用户使用该令牌即可调用卡绑定的模型与分组，费用仅从对应卡额度扣除。重复抽中并合并同一张卡时，保留原令牌并叠加额度，无需修改用户配置。

## 方案

使用独立 `GachaCardToken` 实体，不复用普通 `Token`：

- 令牌仅绑定一张 `UserGachaCard`，不承担普通令牌的余额、分组或模型配置职责。
- 数据库存储令牌不可逆哈希、前缀、卡片 ID、用户 ID、状态、创建和撤销时间；不保存可恢复的完整令牌。
- 完整 `sk-...` 仅在抽卡结果接口返回一次。卡库后续仅展示掩码与前缀，并提供复制当前令牌不可用的明确提示。
- 同模型、同分组卡合并时不创建新令牌，原卡令牌继续生效且自动获得新增额度。
- 新卡发放和令牌创建必须处于同一数据库事务，失败时整体回滚。

## 认证与调用

1. 请求从既有 `Authorization: Bearer sk-...`、Anthropic、Gemini、WebSocket 入口提取密钥。
2. 普通 Token 认证未命中时，查询卡片令牌哈希。
3. 成功后校验卡片令牌状态、卡归属、用户状态、卡状态、有效期与剩余额度。
4. 将用户、卡 ID、卡绑定分组、单模型限制写入请求上下文。
5. 后续分组选择与模型限制沿用既有上下文和分发逻辑；BillingSession 识别卡 ID 后复用现有卡额度预扣、结算与退款链路。
6. 使用卡片令牌时，忽略并拒绝冲突的 `New-Api-Card` 头；保留该头给普通令牌作为兼容入口。

## 行为规则

- 卡片令牌只能调用卡的 `ModelName`，只能使用卡的 `Group`。
- 卡用尽、过期、禁用、令牌被撤销或用户被禁用时，返回与普通令牌一致的认证/权限错误，不回退扣除钱包或普通令牌余额。
- 卡片令牌不能选择指定渠道、不能跨组重试、不能配置 IP 白名单或自动分组。
- 用户撤销令牌后，卡片与剩余额度保持不变；本次设计不提供重新生成令牌入口，避免完整令牌无法安全再次展示的问题。后续可单独增加“重置令牌”流程。

## API 与前端

- 抽卡响应中每个新建卡返回一次 `card_token`；合并卡返回 `card_token_created: false`，不返回原始令牌。
- 卡库接口返回 `token_masked`、`token_status`，不返回完整令牌。
- 卡库卡片移除 `New-Api-Card` 使用提示，替换为令牌状态、首发令牌展示和复制控件。
- 增加用户侧撤销卡片令牌接口，要求卡片归属校验；不提供管理端读取完整令牌的能力。

## 安全与迁移

- 使用加密安全随机数生成足够熵的令牌；数据库仅保存固定长度哈希并建立唯一索引。
- 查询采用哈希精确匹配；日志、错误与审计记录不得输出完整令牌。
- 现有卡默认没有令牌；迁移后为历史可用卡补发令牌，但完整值不可回显，用户通过卡库“重置令牌”取得新值。因此实现范围需包含安全的令牌重置接口和一次性显示机制。
- 旧 `New-Api-Card` 路径保持可用，不改变普通 Token 行为。

## 测试

- 模型层：新卡创建令牌、重复合并沿用令牌、哈希查询、撤销与历史卡补发。
- 中间件：卡片令牌认证、模型/分组限制、失效卡拒绝、与 `New-Api-Card` 冲突拒绝、普通令牌无回归。
- 计费：卡片令牌调用仅扣卡额度，失败退款正确，日志保留 `gacha_card_id`。
- 前端：令牌首发显示、掩码展示、复制、重置确认和令牌不泄露回归。
